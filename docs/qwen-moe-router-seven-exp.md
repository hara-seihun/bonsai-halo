# The seven-exp router is locally accurate but has a small decode-time prize

**Question.** Does the exact-real router observation that selects raw top-eight logits and normalizes only seven exponentials survive *all forty* actual routed producer layers, and is it worth a native port ahead of the Q8/expert path? [Kelana's construction](../../kelana/research/moe/router-observer/README.md) proves the real-arithmetic identity and shows an FP32 counterexample to bitwise equivalence; its first actual-route panel covered only layer 0.

`tools/qwen-moe/router_seven_exp.py` joins both disjoint 64-token, forty-layer captures of the selected GGUF's **actual post-attention normalized producers, eight IDs, native normalized scores and all eight complete 2,048-dimensional down outputs** with the installed F32 router matrices. It computes stored-F32 weight/input dots in FP64, checks raw-logit top-eight sets against the native captures, rounds the eight selected logits to FP32, and computes `expf(l_j-max)`, eight-term FP32 sum and division using NumPy FP32. It compares scores and the complete weighted routed sum against the *captured native normalized scores*, with unchanged native down outputs. This is an offline alternative score map, not the precise HIP dot/exp/reduction order. Capture callbacks may change graph boundaries, and this is local error rather than complete-model language loss.

The [forty-layer source/model/capture-hashed receipt](../../data/qwen-moe/router-seven-exp/receipt.json) includes each layer's input and router-tensor hashes, output sums, worst token and route margin. The *observed* local error is small even where raw-logit margins are tight, extending the layer-0 result from 239 to 5,120 route decisions across two text splits. It does not guarantee future generated IDs, long continuations, FP32 top-k ties, or held language quality. Native score changes are nonzero, so this is not an exact scheduling patch.

**Cost boundary and decision.** The seven-exp map replaces 256 exp evaluations per routed layer with seven, but retains the full 256-row router matvec, top-eight comparison, eight selected expert projections and sum. On the already recorded [counter-free profiled selected-runtime depth-1024 decode trace](qwen-moe-q8-unprofiled.md), *all forty* fused `router/topk` device dispatches together take **0.296719 ms/token** out of **20.397993 ms/token** summed device duration (**1.45465%**). This is a generous ceiling for an intervention restricted to eliminating that traced kernel time entirely, including its non-exp work; seven-exp can remove less. The separately measured unprofiled 19.635-ms wall cannot be subtracted from the profiled duration, and this is not a wall-TPS ceiling or an ISA-independent lower bound. The native width-dependent top-k graph has a known numerical fork; any new fused map needs complete-head and state comparison plus held loss, not just route-set agreement. **Do not prioritize this native port over the ordinary Q8/expert execution diagnosis:** the current fused top-k time is too small for its 249 fewer exponentials to be a major whole-model decode win. Keep the construction as an explicit alternative if a future complete-region consumer absorbs it at no extra launch or if the router becomes a measured bottleneck at another shape.

No GPU run, installed executable, model image, service or serving default changed in this iteration. Reproduce the CPU panel with `OPENBLAS_NUM_THREADS=4 python3 tools/qwen-moe/router_seven_exp.py --first 0 --last 10` (then 10–20, 20–30, 30–40) and `--aggregate`; raw layer receipts and data operations are documented in the linked data README.
