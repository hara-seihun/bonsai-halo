# Qwen counter hole follows the profiler kernel selection

The original native counter panel's 395 consecutive all-zero read-counter dispatches are not a property of the Qwen weight reader. On the **same original installed `b4c67ced9` binary**, model, no-warmup two-token request, batch/ubatch 512/256 and counter family, limiting `rocprofv3 --kernel-include-regex` to `.*mul_mat_vec_q.*` gives positive read counters on **all 582/582 quantized matvec calls**. The original broad regex selected 862 matvec calls, including floating matvecs, and had only 315/582 positive quantized calls. All **267 originally zero quantized dispatch IDs** become positive under the narrow selector; their kernel names and grids match by dispatch ID. Both Q6 vocabulary heads are positive, rather than only the second. The profiler selection is a causal lever on *reported values*, not evidence that selecting fewer kernels changed model weight accesses.

The bounded four-arm experiment separates two tempting explanations:

| Same two-token workload; selected counters | Profiler selection | Selected dispatches | Quantized calls with positive counters | All-zero run |
| --- | --- | ---: | ---: | --- |
| Original, four size metrics | broad, quantized + float | 862 | 315/582 | 395, dispatch 379–1858 |
| Disable HIP graphs, four metrics | broad | 862 | 314/582 | same 395 |
| One 128-byte metric | broad | 862 | 314/582 | same 395 |
| One 128-byte metric | quantized only | 582 | 582/582 | none |
| Four size metrics | quantized only | 582 | **582/582** | **none** |

The broad controls differ at just the first selected dispatch (239), whose counter changes from positive in the original to zero in both replays. All three retain the identical 395-dispatch hole, including the first full-vocabulary Q6 head. The `GGML_CUDA_DISABLE_GRAPHS=1` control eliminates graphs but not that hole; reducing four size counters to one does not repair it either. Narrow selection with all four original metrics repairs it. These controls establish a **profiler-selection-dependent missing-measurement failure**, not whether float-kernel collection, filter implementation, HSA context handling or another internal interaction caused it. Do not attribute the run to graph capture or counter multiplexing.

With the narrow selector, every quantized family reports 0.5003–0.5035 of its one-read packed image in the same GL2C read-request metric (Q8 width 8192: 80/80 calls, 0.500273; Q4 routed: 80/80, 0.500685; Q6 head: 2/2, 0.503466). The [known-stream calibration](qwen-moe-gl2c-calibration.md) gives essentially half the kernel's explicit read size on 16–256 MiB buffers, including inputs larger than cache. The *hole* is closed by narrowing the selection, but the counter still is **not an independently calibrated physical DRAM-byte total**. Dividing by one-half is a conditional instruction-side interpretation, not proof of one actual DRAM traversal or of no native rereads. Counter-collected durations also are not unprofiled full-model phase time.

Use `tools/run-batch-compare` around the profiler; this panel used `--runtime-max 40s --memory-gib 30 --host-reserve-gib 4 --exec`, the preserved original installed binary, and `-o jsonl -r 1 -d 0 -b 512 -ub 256 -t 8 -ngl 99 -fa on -p 0 -n 2 --no-warmup`. Every raw CSV, profiler stderr/benchmark output, wrapper clock and service restoration log lives below `../../data/qwen-moe/q8-native/{graph-off,one-broad,single-metric,four-qonly}/`. The complete pinned model hash and original binary hashes are in the [original receipt](../../data/qwen-moe/q8-native/receipt.json). All four new wrapper runs restored `bonsai-halo.service`; the GPU reservation is free. Neither selected Qwen image, executable nor resident Bonsai model changed.

`q8_native.py` now reports its **observed** zero-counter quantized-call count and warns only when data are actually missing, instead of labeling every new repaired panel as the original 395-zero panel. The narrow four-metric panel is a valid observed-request-counter series for all matched quantized calls, but its near-half-image readings are not a new whole-model speed result. **Next:** if actual DRAM transactions are needed, calibrate a physical DRAM metric with known streams and diagnose its attribution before applying it to an unprofiled-depth-1024 Q8/expert phase; otherwise spend the next engine iteration on complete-model native J16/64 prompt dispatch or an unprofiled ordinary Q8 consumer. Avoid recoding Q8 weights on the basis of the old fourfold traffic estimate.
