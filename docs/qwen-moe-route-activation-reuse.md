# A repeated route does not repeat its packed gate/up input

Qwen3.6-35B-A3B selects the same layer-0 expert many times over the two captured real-text prompts. Could a persistent dictionary keyed by `(expert, K-block, packed activation)` reuse exact gate/up integer dots, rather than only caching weight bytes? On the **actual post-attention producer** of the installed GGUF, this exact-input memoization grammar has no hits. The native grouped `mul_mat_id` already prepares one input per token for all eight gate/up experts; it must not be counted as a new saving.

| Layer-0 prompt | Routed assignments | Assignments to an already seen expert | Distinct Q8_1 producer 32-code blocks | Equal blocks at fixed K | Equal blocks with free K permutation | Equal complete 2048-code inputs |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Train, 113 tokens | 904 | 735 | 7,232 | 0 | 0 | 0 |
| Held, 126 tokens | 1,008 | 820 | 8,064 | 0 | 0 | 0 |
| Combined, 239 tokens | 1,912 | 1,708 | 15,296 | 0 | 0 | 0 |

Each finite 32-float block was coded using the installed `quantize_q8_1` rule: `d = max(abs(x))/127`, then `roundf(x/d)` to signed eight-bit codes. All producer floats are finite, and none of these blocks has all-zero codes. Equality of all 32 codes is **necessary but not sufficient** for a byte-identical operand: the native block also stores a rounded FP16 scale and a rounded FP16 sum. Since there is no code collision even with free permutation of the K-block positions across all 239 tokens, checking these additional fields cannot create a hit. The rule is checked against the native `quantize.cu` source hash in the receipt; the CPU rounding of half-integer quotients is not asserted bit-for-bit with the GPU for arbitrary inputs, and the observed no-collision applies to the stated finite CPU-coded producer domain. This is not a proof that a different approximate code cannot coalesce blocks, nor that two distinct inputs cannot happen to have the same output after a particular weight dot.

The observed input has 64 Q8_1 blocks, 36 bytes each, or **2,304 prepared operand bytes per token per layer**. If every layer behaved like layer 0, even eliminating every one of these bytes would save only 92,160 bytes/token, **0.00351%** of the 2,626,187,904-byte conditional one-read whole-model weight stream. That figure does not bound arithmetic, cache or latency wins from a different consumer. The tested exact memoization returns zero hits before paying for at least 64 block fingerprints/lookups per token, cache state, fanout, or checking additional scale/sum fields. Repeated expert IDs alone therefore do not provide the purported route-conditioned exact dot reuse on this producer. The independent down-operand study also finds no equal blocks **across different experts on one token**; this report instead tests **one shared gate/up producer across different tokens**, including repeated routes.

The [receipt](../../data/qwen-moe/route-activation-reuse/receipt.json) hashes the source, both complete producer/route arrays, capture provenance, installed-runtime receipt and native quantizer source. The source and model identity are inherited from the [original capture](qwen-moe-routes.md). No GPU, executable, model image, native map or service changed. This rules out only an equality-keyed *existing-code* route memoizer on two layer-0 prompt captures. A useful next route-specific question is a changed packed producer/weight label learned against broad **quantized** producers across layers, with a complete paid image and disjoint language loss, not a larger hash table for this code. The sub-bit pilot's improved local responses and poor whole-model loss make that acceptance boundary necessary.
