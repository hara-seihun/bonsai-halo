# Full-model throughput with the September 21 optimizations

the project owner requested a fresh whole-model measurement of single and batched generation with the available optimizations combined. This panel fixes source at `83f0478307d166933fc39c2d5841c6792a3128e9`, rather than mixing results from the continuing optimization lane.

Raw runs, executable hashes and the derived `summary.json` are in [`full-tps-20260921-2255`](../../../data/bonsai2/batch-comparison/full-tps-20260921-2255/). All 64 layers run on the Radeon 8060S. Model loading and static preparation are outside timing. The maintained runner serializes GPU use, bounds allocations, pauses serving and requests the high performance level with `--pin-clock`. That setting is not a fixed shader frequency.

## Generation

| Configuration | Aggregate tokens/s | Tokens/s per stream |
|---|---:|---:|
| Single, Q4 DFlash, FP32 state, wide-deployed prompt route | 69.45 | 69.45 |
| Single, Q4 DFlash, INT8 state, A4 prompt route and sequence input | 62.08 | 62.08 |
| Single, no drafter, INT8 state | 33.70 | 33.70 |
| Eight streams, mode 19, INT8 state, A4 sequence input selected | 132.55 | 16.57 |
| 32 streams, mode 19, INT8 state, A4 sequence input | 383.32 | 11.98 |

The drafted single-stream figures are the median of ten per-prompt medians, each over three rounds. Prompts cover prose, code, arithmetic and explanation; generation stops at EOS or 192 tokens. FP32-state per-prompt medians span 51.42 to 113.35 tokens/s; INT8-state medians span 44.39 to 93.49. Pooled generated tokens divided by logged generation time give approximately 71.59 and 62.96 tokens/s respectively. Those pooled calculations use the log's rounded seconds.

Batch figures are three-round medians of 64 greedy steps per stream with distinct short prompts. Context capacity is 1024, not a 1024-token starting context. The driver emits and feeds back EOS through the fixed step count. Batch-32 rounds were 416.86, 383.32 and 373.25 tokens/s. Batch-eight rounds were 134.32, 132.55 and 131.07. No speculative drafter runs in batch mode.

Below 32 rows mode 19 does not take the wide A4 module or wide sequence input projection. Selecting their flags therefore does not mean those kernels execute at eight streams or one stream. The plain single row above is measured through the batch driver at one stream, not through the drafted engine path.

Turning on every approximate option did not give the fastest single-stream configuration in this panel. The two drafted configurations change both state and prompt arithmetic, and run in separate processes; this is a comparison of configurations, not an isolated attribution to one option. Their output digests differ, so the approximate combination is not an exact-output substitute for the FP32-state configuration. The Q4 drafter alone is lossless against its target, but that does not undo approximations made to the target itself.

## Prompt processing

Mode 19 with INT8 state, A4 sequence input, 256-row passes and a tail-only vocabulary head processed a 768-token document at **862.22 tokens/s median**. The three rounds were 778.28, 935.50 and 862.22. This is full-model prefill, separate from generation, using the batch driver's document workload.

## Commands

Build once at the recorded source:

```sh
make -j8 bonsai-halo tools/batch_compare
```

Batch generation and prefill:

```sh
tools/run-batch-compare --pin-clock --tag full-tps-20260921-2255/batch \
  --modes 19 --gdn-state 3 --seq-quant a4 --streams 1,8,32 --slots 32 \
  --context 1024 --gen-steps 64 --rounds 3 --only prefill,decode \
  --prefill-rows 256 --prefill-tokens 768 --head-rows tail --warmup-steps 8
```

Drafted single stream with all approximate options:

```sh
HALO_GDN_STATE=i8 HALO_SEQ_QUANT=a4 tools/run-batch-compare --pin-clock --engine \
  --bench --context 4096 --dflash ../../data/bonsai2/drafters/dflash2.safetensors \
  --draft-weights q4 --prefill-ffn wide-commit-a4 --pass-rows 256 \
  --prompts bench/drafter-prompts.txt -n 192 --sweep-rounds 3
```

For the faster single-stream configuration, use the same command with `HALO_GDN_STATE=f32`, `HALO_SEQ_QUANT=a8` and `--prefill-ffn wide-deployed`. Both configurations use the same executable. Single-stream context capacity is 4096; the ten starting prompts contain 23 to 49 tokens.

These measurements change no serving default. New kernel work after the pinned source is outside this panel.
