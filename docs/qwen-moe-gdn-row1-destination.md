# Missing swapped Qwen sequence-1 K/V is not a saved-cell permutation

The [four-arm matched transition](qwen-moe-gdn-permutation-equiv.md) and [complete zero-cell census](qwen-moe-gdn-zero-key.md) show that swapping the physical order of two logical sequences on a 31+1 generated step leaves logical sequence 1's newest K and V cell all zero in all ten attention layers, under both gathered and guarded-direct GDN. Is the correct nonzero cell merely stored at another saved position or logical stream?

`tools/qwen-moe/gdn_row1_destination.py` compares the normal logical-slot-1, position-9 K/V cell (512 FP16 words each) against **every** saved cell of the same layer and K/V kind in the matching swapped arm: 32 streams × 10 positions × 10 layers × 2 kinds × 2 independent arm pairs = **12,800 whole-cell comparisons**. Both post-state files have the same region layout. All 20 normal cells contain 512 nonzero FP16 words; all 20 swapped target cells contain zero nonzero words. There are **zero exact relocations** in either arm. Even the nearest saved candidate agrees in at most **4/512 FP16 words** across all 40 target/arm combinations. The metadata for all 32 streams is byte-identical between normal and swapped states, including every cell's sequence IDs, position and two spatial position components. In particular, slot 1's newest metadata remains logical ID 1 at `(position,x,y)=(9,9,9)` despite its zero data.

[The native host-index and isolated scatter follow-up](qwen-moe-gdn-row1-producer.md) records the correct reordered first-segment target (stream 1, cell 9, index 265) despite the zero saved K/V at all ten layers; a standalone 31-row HIP `SET_ROWS` graph reproduces all 16,384 expected FP16 halves. This narrows the next probe to unsaved producer, full-graph fusion/device input and pre-export cache, not a host index arithmetic fix. The diagnostic rebuild does not reproduce the original gathered reordered head/state and is not an accepted runtime change.

Thus a **pure post-state whole-cell permutation of unchanged K/V payloads** cannot produce this swapped image from the normal one, nor can a serializer fix this panel by simply swapping the saved logical slots. This is a finite representation argument about these particular captured post-state bytes; it does not rule out a wrong write address *combined with overwriting or dropping data*, a changed pre-cache producer, or a device-to-host export failure. The row-4 temporal IMRoPE displacement is a different observation. A native repair should side-band capture row 1's pre-RoPE K/V producer and actual destination index and device cell before export, without a graph-cut callback, rather than remap serialized cells after the fact. Keep full heads and complete state as the acceptance contract.
