# Exact recurrent-state coding does not replace the no-copy GDN schedule

The installed Qwen3.6-35B-A3B GDN writer removes **4,026,531,840 logical bytes of intermediate state traffic per 32-row generated step** on its stable-identity domain. Dynamic row reorders still use the gathered schedule. Can an exact, independently addressable packed coordinate substantially reduce that schedule's full-state copy instead of carrying the physical-row permutation? This complete saved-state experiment says no for the tested zstd/FP32-shuffle family: its best paid 16-KiB-page image saves **9.2184%** of the S payload, before decode, bit transpose and re-encode on each update. The stronger independent next question is the no-copy source-address schedule on reordered real requests, with full-head and serialized-state acceptance.

## Domain and construction

Input is the installed revision `7861dc7`'s matched, generated 32-sequence context after 512 actual prompt tokens per sequence and five complete-vocabulary greedy generated calls. The saved entire context is [`512-final-control.endstate`](../../data/qwen-moe/gdn-context/512-final-control.endstate), SHA-256 `78589e0c227cb34c7de21eb675cd76a8862dc4473e1300497bf8f19618182af2`; its fused twin has the same complete-state SHA-256. [The originating full-model panel](qwen-moe-gdn-context.md) establishes exact heads and state. This is not an artificial random-FP32 vector or a changed numerical map.

The source serializer writes thirty non-null GDN S layers last in the hybrid context. The checker locates this suffix by size and validates each `(F32 type=0, row_bytes=2,097,152)` header. It then scans **30 × 32 rows × 524,288 FP32 words = 2,013,265,920 raw S bytes**, never counting the context metadata or attention/conv cache as state savings. Each row is divided into independent fixed-sized pages. A page is either byte-identical, byte-shuffled by FP32 byte position, or bit-shuffled in independent groups of eight FP32 words; zstd level 1 then compresses that page. A paid 8-byte offset per page permits independent lookup. The tool decompresses and inverts *every* page and compares it byte-for-byte to the original before crediting any saving. All six decoded payload SHA-256 values equal `5cefb9747133e66124e8b33308b48b33e200818c99ee8cda8339bb83b8afb602`. No scale, rounding or floating operation is changed by the representation; native execution must still recover the exact input words and preserve the existing recurrence arithmetic.

All 960 full rows and every page have nonzero bytes; a zero-page-only exact copy elimination has **zero hits** here. The bit-shuffle improvement is real but moderate; unlike source-address in-place updating, compressed S must be read and decoded, the FP32 recurrence evaluated, then encoded and written. Even granting *free* bit transpose and codec instructions and charging only the two compressed intermediate transfers, the best tested image removes **371,183,476 bytes per complete 32-row step** relative to the two raw intermediate transfers, versus **4,026,531,840 bytes** eliminated by no-copy addressing. That is a family-specific **9.218% byte reduction**, not a universal compression lower bound. At the measured 242 GB/s bandwidth comparator, the saved bytes correspond to **1.534 ms of ideal streaming time**; it is not a measured wall-time upper bound or a native kernel speedup. The selected gather's roughly 19 ms is device timing under its own scheduling, so proportional time should not be asserted without a native codec. The decoder additionally entails dependent page-offset loads, bit transposition, scratch traffic and per-step re-encoding, all unpriced on this GPU. There is no reason to port this tested family ahead of the exact physical-source writer experiment.

## Custody and limits

[`gdn_state_entropy.py`](../tools/qwen-moe/gdn_state_entropy.py) computes and checks the entire suffix; its SHA-256 at this run was `890bc5c70b53957470e460963de8af6f7dcefc761a2606356cccf94d97610644`. The six per-arm source/image-size/decode-hash receipts are in [`gdn-state-entropy/`](../../data/qwen-moe/gdn-state-entropy/). They retain each layer's compressed size, page extrema, offset bytes, source hash and complete reconstructed-payload digest. The input whole-state and the matched-head/full-state acceptance remain with the originating panel. CPU-only analysis: no GPU lock, installed runtime, model image, service or native scheduling was changed. This does not reject a different codec, a lossy state coordinate with complete-model quality evidence, or a no-copy row permutation. It rejects **this exact page-code family as the priority repair for dynamic GDN reorders** on the measured occupied state.
