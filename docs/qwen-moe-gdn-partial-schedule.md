# Fixed-destination partial GDN state updates need at most one row of scratch

The [source-owned fanout map](qwen-moe-gdn-fanout.md) obtains zero intermediate full rows by carrying a changed logical-to-physical row labeling. If an incomplete dynamic batch must **keep each live row at its current physical destination**, a different exact state-map construction applies: serialize row transitions according to their old-source dependencies, and use one reusable old-row snapshot only for a nontrivial dependency cycle. This handles fanout, inactive sources and arbitrary subsets of active live rows without allocating a gathered 32-row image. It is a semantic schedule, not a native speedup or a repair of the observed 31+1 native graph mismatch.

## Contract and proof

Let `L` be the live physical rows, `D ⊆ L` the active destinations, and `s:D→L` the old-source map, possibly with repetitions. The desired gathered state is `C'[d]=F_d(C[s(d)])` for `d∈D`, with inactive rows unchanged. `F_d` is a row-local transition using fixed token operands; the single-row implementation must perform the *same finite FP32 operations in the same order* as the gathered reference for a native bit-identity claim. The abstract proof treats each row transition as an atomic read of its complete old source followed by a write of its complete destination. It says nothing about GDN's intermediate graph operands or actual compiler execution.

Create an edge `d → s(d)` whenever `d≠s(d)` and `s(d)∈D`. A destination `v` may be overwritten only after **all pending readers** with source `v` have executed. Self-sourcing is safe within a row transaction because its old state is read before its own write. Since each destination has at most one outgoing edge, every component has at most one directed nontrivial cycle. Without cycles, repeatedly execute a destination with no pending readers; this is a topological schedule, preserving the old source of every operation. An inactive source is never overwritten and places no constraint on the order.

For a nontrivial cycle, save one member's old full row in a reusable buffer. All readers of that member can now read the saved copy; removing those edges breaks the cycle. Run ready destinations until that component has finished, then reuse the same buffer for the next cycle. Every write has read the original source, every inactive row remains unchanged, and the final row label stays fixed. This proof composes across state steps because it reproduces the complete gathered row map after each step. For the serial atomic-row-transaction grammar **without any retained full-row value between transactions**, a nontrivial cycle also makes zero scratch impossible for nondegenerate injective `F_d` on unconstrained independently varying old rows: whichever cycle member writes first destroys its old value while another pending transaction still requires it. Thus the minimum reusable scratch capacity in this grammar is zero when no nontrivial cycle is present, otherwise **one full row**, regardless of cycle count. A cooperative read-all/barrier/write-all kernel or relabeled physical source writer is outside this grammar and can avoid external scratch; this is not an ISA-independent bound.

Example: in a partial batch over four live rows, update `D={0,1}`, `s(0)=1`, `s(1)=0`, retaining 2 and 3. Snapshot old row 0; write new row 0 from old row 1; write new row 1 from the saved row 0. With `s(0)=s(1)=0`, there is no cycle: write row 1 first, then self-source row 0. Scheduling the two writes in the opposite order destroys row 1's old source. A writer that assumes independent CTAs instead of the specified serial order can fail despite the valid abstract schedule.

## Checked result and cost

[`gdn_partial_schedule.py`](../tools/qwen-moe/gdn_partial_schedule.py) exhausts every nonempty destination subset and source assignment for 1–4 live rows: **696 maps**, of which **488 have no nontrivial cycle, 205 have one and 3 have two**. For every map it checks one step and a distinct second step on carried state against an independently gathered nonlinear modular row transition. The checker uses the same dependency criterion, but the expected state is computed from an unmodified old copy. [The receipt](../../data/qwen-moe/gdn-partial-schedule/receipt.json) records the source, installed native bundle and model identities, counts and swap witness. The proof above covers arbitrary finite live sets; finite checking tests its implementation, not native arithmetic.

One Qwen FP32 GDN state row across thirty recurrent layers is `524,288 × 4 × 30 = 62,914,560` bytes. **Per layer** the reusable scratch is 2,097,152 bytes; sharing one allocation across layers requires their update lifetimes to serialize. Saving and consuming one cyclic row adds at least one row write and one row read, or 4,194,304 logical bytes per layer / 125,829,120 across thirty layers, on top of transition traffic. The old source read feeding the save replaces, rather than supplements, the transition's old-source read. Fanout can cause more scratch reads unless one owner shares the loaded source. Dependency ordering may create up to `|D|` serial rounds, and each cycle requires its save/consume ordering; an ordered multi-launch graph or grid synchronization, metadata construction, reduced occupancy and cache behavior can erase any saved gather traffic. These are logical costs, not measured DRAM bytes. The selected stable complete 32-row writer already removes its intermediate copy and is not improved by this construction.

Then on a genuinely incomplete or repeated-source generated batch, compare this fixed-destination serial schedule against the gathered fallback *and* the zero-intermediate source-owned labeling, including full heads, serialized recurrent state, equal occupied prefix and unprofiled wall time. If CTA-level serialization is too expensive, the source-owned relabeling remains the more promising full-batch route. No GPU, installed runtime, model image or resident service changed here.
