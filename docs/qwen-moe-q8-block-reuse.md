# Exact Q8_0 same-input-block reuse on the installed Qwen image

The unprofiled depth-1024 panel assigns 8.333 ms/token to nonexpert Q8 kernels. Could one packed activation dot product be shared across output rows before multiplying each row's Q8 scale? `tools/qwen-moe/q8_block_reuse.py` scans every one of the 250 installed nonembedding, nonexpert Q8_0 tensors (43,909,120 blocks, 1,492,910,080 bytes). It compares the full 34-byte block and the 32 signed code bytes independently, **only at the same input-block coordinate within the same tensor**. This is the coordinate at which rows see the same token activation; identical codes at different K positions do not share a dot on unrestricted inputs. Each tensor payload is hashed; the aggregate receipt hashes every tensor receipt, source, inventory and the local model header. The acquisition receipt verifies the complete model SHA-256 `ac0e2c1189e055faa36eff361580e79c5bd6f8e76bffb4ce547f167d53e31a61`.

**Result:** just 25,903 blocks can reuse a previously occurring same-K block. The code-only count equals the full-block count exactly, and **none of those 25,903 code duplicates is nonzero**. All 320 repeated groups contain zero codes; they appear in five attention QKV tensors (layers 0/1/2/9/21). In the family that reuses one int8 dot when 32 packed signed codes agree, there is therefore **no reusable nonzero dot across output rows anywhere in this installed Q8 bank**. Even granting free detection, addressing and scheduling, full-block dictionary reuse avoids at most 25,903 × 34 = **880,702 Q8 image bytes** in a complete one-read single-token request: **0.03354%** of the modeled 2,626,187,904-byte weight stream. Zero-row skipping's independent free ceiling is 966,144 bytes; these overlapping opportunities must not be added. A fixed-width per-row dictionary index for each K coordinate costs more than it saves: 64,901,058 bytes net *larger* for full blocks; code-only indices (keeping scales separately) lose 64,952,864 bytes. This is a bound in a particular fixed-index grammar, not an optimal compression lower bound.

For unrestricted real input vectors, equality of two int8 code-vector dot maps at a shared K coordinate implies equality of the code vectors (probe unit inputs). Thus this census exhausts **identical-code same-K dot reuse**, but not proportional-vector factoring, different intermediate representations, cross-layer activation equalities, or the nonlinear complete-model map. Q8_0 computes a scaled int8 dot with its own device rounding; real decoded equality and reused dot arithmetic do not prove bit-identical FP32 execution. The byte percentage is a conditional logical one-read budget, not physical DRAM counters or a wall-time bound. The useful next engine question remains ordinary Q8 operand preparation, active waves and actual unprofiled memory traffic, or a consumer that reorganizes the matrix operation rather than interns repeated codes. The sparse-weight and repeated-code shortcuts do not explain the measured phase time.

CPU reproduction, without the GPU or any service change:

```sh
cd .
python3 tools/qwen-moe/q8_block_reuse.py
python3 tools/qwen-moe/q8_block_reuse.py --summarize
```

The first invocation is resumable by tensor; disjoint `--first I --count N` ranges can run independently. [The aggregate and 250 hashed per-tensor receipts](../../data/qwen-moe/q8-block-reuse/receipt.json) have aggregate SHA-256 `5ab6599cd0c6752153b888ab832a2a8c50209402c1ce953b5bbff9b55a1da21a`. The local image header hash is checked against the installed inventory; the full image hash is the separate verified acquisition receipt, not a second 22 GB hash pass. No GPU, runtime, model image or resident service changed.
