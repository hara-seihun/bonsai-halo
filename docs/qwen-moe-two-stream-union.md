# Two independent Qwen generation streams: the MoE image-union ceiling

The [serial generated-route capture](qwen-moe-generated-routes.md) contains two independent 48-step greedy continuations from disjoint 64-token real-text prefixes. Here they form a **paired-stream counterfactual**, not a native batch benchmark. At each aligned step, demand all eight routed outputs in all forty layers from each stream. Each layer's expert bank has 256 separate packed images; a duplicate expert ID across the two streams needs only one **logical full-image read** if an otherwise free batch schedule shares it. The one-read-per-distinct-image union is the minimum demand in this grammar. Router output, Q8_1 activation preparation, the sixteen separate dot products, weighted sums and nonexpert projections still have to run. The native runtime already sorts/group-dispatches `mul_mat_id` assignments by expert; this is an upper bound on additional weight traffic that could be removed, **not** a new grouping method or an incremental native speedup.

Across 48 aligned state pairs, the streams select 30,720 `(layer, expert, stream)` assignments, of which **1,746** are duplicate same-layer expert IDs. They save 3,334,504,448 packed image bytes over the panel, **69,468,843 bytes per two-token step** on average. At the actual three large-layer and 37 ordinary-layer image sizes, distinct routed images cost 1,153,563,989 bytes/step rather than 1,223,032,832. On an independent-uniform eight-of-256 model the expected overlap is only 0.25 experts/layer; this capture averages 0.9094, reflecting nonuniform routes and shared model behavior, not a uniform-random control experiment. Individual aligned steps save 5,701,632–166,461,440 bytes. Exhaustively pairing the 48 independently reachable states from each continuation (2,304 *possible* pairs, not one causal run) yields mean 69,943,950 bytes, so the aligned result is not an unusual lag selection on these two samples.

The decisive denominator is the complete model, not the routed bank in isolation. For two separate one-read single-token steps the declared image demand is 5,252,375,808 bytes. Reading their identical nonexpert image once per batch step already removes 2,014,669,312 bytes, leaving 3,237,706,496 bytes (including two embedding rows). Even if the routed images cost no extra gathering, scheduling or cache management, the observed same-expert image union removes **only 2.1456% of that remaining grouped one-read demand** (1.3226% of two separate steps). Combined free nonexpert and routed-image sharing removes 39.6799% of two separate one-read image streams; **38.36 percentage points are nonexpert sharing**, not an MoE route discovery. This bounds unchanged-image *cross-stream duplicate reads at width two* on these observed states. It does not bound tile re-use within each image, packed-code transformations, producer/consumer fusion, larger batches, or physical DRAM traffic and is not a latency or TPS ceiling.

The exact count follows from set union: for each layer `l` and paired state `(t,u)`, `|A_l,t ∪ B_l,u| = 16 - |A_l,t ∩ B_l,u|`, with each image charged the inventory's `bank_bytes[l]/256`. Each route contains eight distinct IDs. No equality of FP32 results follows from the real-number sharing argument: changing a native batch width can change reductions or router behavior. The callback requested top-k views and cut graph fusion; plain and observed generated IDs agreed within each process, but the captured routes are not a no-cut selected serving trace. A batch-width implementation must preserve its selected arithmetic contract independently.

**Decision.** A width-two expert-cache/prefetch scheme that only recognizes exact same-bank image identities is a small complete-image opportunity even under free sharing. First measure the installed *unprofiled* native two-independent-stream `mul_mat_id` cost, ordinary Q8 phases, physical image traffic and requested logit behavior. If grouped expert reads already approach the union, another route-aware cache cannot claim these bytes. Unlike the serial 32 MiB cross-token cache result, this bound concerns within-step, same-layer batching and does not require retaining 40 layers of images across a token boundary. For a larger stream batch, obtain real multi-stream routes rather than exponentiating this two-stream observation.
