# Parallel fixed-destination GDN updates trade scratch for serial rounds

The [partial-batch dependency construction](qwen-moe-gdn-partial-schedule.md) proves that **one reusable row** of scratch suffices for an arbitrary fixed-destination old-source map, but its row transactions can serialize an entire active batch. This result prices the other side of that trade: the number of synchronized transition rounds if the old-row snapshots are all taken **once, before the transitions**, and kept live until every destination has finished. It is a semantic scheduling bound, not a native timing or a repair for the rejected Qwen 31+1 graph.

## Exact grammar and optimum

Let `D` be active physical destinations, and `s:D→L` an arbitrary old-source map, including fanout and inactive sources. A destination `d` writes `F_d(old[s(d)])` without changing its physical label; inactive rows remain untouched. Before transitions, snapshot any `S⊆D` into `|S|` row-sized buffers. The subsequent parallel rounds execute disjoint whole-row atomic transitions, with **no intra-round read-all barrier**: an unsaved old source cannot be overwritten in the same round as a distinct reader or in an earlier round. A self-read is loaded before its own write. Snapshots and all fixed token operands are from the original state. This grammar excludes a source-owned relabeling, cooperative read-all/barrier/write-all, a new snapshot between rounds and recomputation of an old row from other information.

For each distinct reader `d` whose source `v=s(d)` is also an active destination, draw the precedence edge `d→v`. Snapshotting `v` deletes **all edges ending at `v`**. If the remaining graph has a directed cycle, no schedule exists. Otherwise its **longest directed path measured in vertices** is exactly the minimum number of transition rounds. The earliest-round topological schedule achieves it: each round runs all pending destinations with no pending distinct readers of its old row. Conversely every edge requires its reader to be in a strictly earlier round, and a directed path of `r` vertices needs at least `r` rounds. With independently varying old rows and distinguishable row transitions, no same-round write/read race can promise the gathered observation. This argument is independent of Qwen's FP32 details; native bit-identity additionally requires identical row operands, operation order and compiler arithmetic.

For a cycle of `L` active rows, at least one snapshot is necessary. With `1≤k≤L` snapshots, the best placement divides the cycle into `k` paths. The largest gap is at least `ceil(L/k)` vertices, and placing snapshots as evenly as possible attains it. Thus **minimum rounds = `ceil(L/k)`**, not merely the one-row scratch bound. A 32-cycle needs 32 serial transition rounds with one saved row, four rounds with eight saved rows, two with sixteen and one round only by saving all 32. It is a conditional worst-case source map, **not** an observed route in the current generated panel.

## Checked finite map and Qwen cost

[`gdn_parallel_scratch.py`](../tools/qwen-moe/gdn_parallel_scratch.py) enumerates **all 696** nonempty destination/source maps with one to four live rows (including fanout and inactive sources). It tries every static snapshot subset, finds the minimum-round schedule, independently computes the gathered nonlinear transition from immutable old rows, and checks a second transition on the carried state. **208 maps** have a cycle with zero snapshots. For the four-cycle the minimum-round frontier at `k=0…4` is **infeasible, 4, 2, 2, 1**. [The source/model/installed-bundle/failed-trace-hashed receipt](../../data/qwen-moe/gdn-parallel-scratch/receipt.json) stores the complete histogram and 32-cycle bounds. Finite checking tests the construction; the edge/path proof covers any finite map.

A Qwen FP32 recurrent state row has 524,288 values = **2,097,152 bytes per layer**. The 30 recurrent layers can reuse one scratch allocation if their update lifetimes are serialized. In the declared grammar a `k`-row static snapshot entails `k × 2,097,152` peak scratch bytes and at least `2k × 2,097,152 × 30` logical intermediate write/read bytes across layers, before the original transition loads/stores, synchronization, graph construction or occupancy. At the 32-cycle's four-round `k=8` point this is **16 MiB scratch and 1,006,632,960 logical intermediate bytes** across the model; one-round `k=32` consumes **64 MiB and 4,026,531,840 logical intermediate bytes**, equal to the selected gathered route's intermediate payload. These are logical bytes, not DRAM transactions or wall time. One saved row's 32 transition rounds and barriers can cost far more than the bytes it avoids. The source-owned carried-label map avoids this particular scratch/round compromise when the complete active source set can be handled; that route has different metadata and scheduling costs.

The *actually retained* rejected swap splits into 31 identity rows and one disjoint identity row, so both subcalls have **zero dependency edges and one round each**. This bound proves that adding snapshots or parallel dependency scheduling cannot fix its observed all-logit native mismatch. Before any dynamic native port, locate that split's first divergent GDN operand/cache layer on the unchanged graph. For a genuine dynamic partial batch with nontrivial dependency, capture its actual source map, compute this frontier and compare full heads, serialized state and unprofiled whole-model time against gather and carried-label alternatives. Neither the installed writer nor the resident service changes here.
