# The long Qwen verification-width fork survives disabling CUDA fusion

The [safe router-allocation experiment](qwen-moe-router-lifetime.md) matched the first five target-only rows at widths 1/2/4/8 but failed on a 96-step replay: width four first differs at generated row 12, width eight at row 1, and width four reverses the near-tie greedy decision at row 71. That left a critical ambiguity: was the longer failure merely another router-fusion dispatch boundary?

A matched no-graph-cut panel uses the same packaged native source `81326f7`, the same `batch-logits-alloc` executable and pinned GGUF, the same list prompt, 2048 context, 512 batch/256 ubatch and all 248,320 vocabulary logits for every row. Both arms produce **the same 16 plain greedy IDs**, which also equal the first 16 IDs of the retained 96-step run. The only change is `GGML_CUDA_DISABLE_FUSION=1`; `ggml_cuda_compute_forward` reads this variable and bypasses all CUDA fusion selection. Each arm regenerates its own width-one reference, then resets state and replays the identical tokens at widths 1, 2, 4 and 8. The GPU wrapper restored the resident service on both bounded panels. These are numerical-map diagnostics, not a speed comparison.

| Width / first-call offset | Fusion enabled: differing rows / first | All CUDA fusion disabled: differing rows / first |
| --- | ---: | ---: |
| 1 / 0 | 0/17 | 0/17 |
| 2 / 0, 1 | 0/17 each | 0/17 each |
| 4 / 0, 1, 2, 3 | 5/17 each; row **12** | 5/17 each; row **12** |
| 8 / 0 | 16/17; row **1** | 16/17; row **1** |

At each arm's first changed row, **all 248,320 FP32 logits differ**. The numerical magnitudes change between arms (width-four row-12 maximum absolute difference 1.180918 versus .947369), so this is not a claim that the two arms compute identical logits. It is a stronger negative for the *proposed repair*: eliminating every CUDA fusion does not restore the width-invariant plain target map on the longer replay. Earlier four-token fusion-disable identity remains true on its short panel; it did not establish an invariant at longer occupied states or width eight. The width-four row-12 failure occurs in all four offsets, which put that token at each of the four distinct within-batch positions. This disfavors a simple row-lane misindex at that position, but does not localize a GDN, attention, or graph-state failure.

The panel charges no new representation bytes and changes no selected image, runtime, serving default or MTP policy. It rejects another top-k-only numerical patch as a sufficient **long-context** repair; the fusion boundary may still be one independent short-width discrepancy. The next decisive experiment is a no-cut state/activation comparison around the first width-eight step and width-four row 12, or a controlled GDN-versus-attention branch intervention on the *same* 16-step fixture. Callback reads which split the graph are not noninvasive observations; [the earlier callback experiment](qwen-moe-batch-logits.md) already proved they can change the map. Check finite full-head output and state after any proposed exact repair, then replay token 71 and price complete-model rates. The concurrently owned 32-stream GDN indexing candidate is a separate traffic change, not an MTP fix by implication.

Both bounded commands used `tools/run-batch-compare --runtime-max 40s --memory-gib 30 --host-reserve-gib 4 --exec`; the receipt gives the exact driver, model, runtime and input. The matched source's 96-step no-cut output is also hashed for comparison. Each wrapper records service restoration; this diagnostic did not install a runtime.
