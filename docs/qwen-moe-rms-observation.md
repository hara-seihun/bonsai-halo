# The selected Qwen post-MoE RMSNorm observation

Can a cheaper exact routed-expert consumer carry only the direction of the post-MoE vector because the next layer applies RMSNorm? [Kelana's complete-vector fiber theorem](../../kelana/research/moe/rms-observer/README.md) answers this **ideal-real boundary** question: with positive epsilon and all nonzero gain coordinates, RMSNorm has an explicit inverse on its image and singleton fibers. The theorem also gives a conditional lower error modulus; it does not constrain a weaker final-logit observation or native FP32 rounding.

## Installed-image and graph facts

In the selected native graph (`src/models/qwen35moe.cpp`, `graph::graph`), each layer forms `post_moe = ffn_out + ffn_residual`. Layers 0–38 feed that vector into the **next** layer's `attn_norm`; layer 39 feeds `output_norm` before the head. The installed GGUF declares RMS epsilon **9.999999974752427e-7**. All forty of these particular 2,048-wide gain vectors are F32, finite and nonzero at all **81,920** coordinates; the minimum absolute gain is **0.12109375**. [The source/inventory/acquisition/payload-hashed CPU receipt](../../data/qwen-moe/rms-observation/receipt.json) identifies every tensor and its bytes. These are properties of the pinned installed model, not of all Qwen releases.

At the complete next-norm vector boundary, positive-ray labels are therefore **not an exact ideal-real quotient** of the post-add vector. For a fixed residual-plus-shared term, the routed sum is injectively observed as well. This is not a claim that a whole-map program must materialize routed expert outputs, that exact FP32 outputs distinguish every distinct input, or that the vocabulary head distinguishes all next-layer states. A paid joint carrier may still match the final requested observation without reconstructing this intermediate.

Radial perturbations can have tiny numerical effect despite the exact distinction: the theorem's conservative response coefficient using the installed minimum gain and an *illustrative, unmeasured* input norm cap of `√2048` is only about **1.210935e-7**. Approximate work needs measured real post-add outputs and held complete-model language loss. The [earlier projective routed-sum oracle](qwen-moe-routed-norm-observer.md) omitted the residual and shared branch, so its epsilon-free isolated-vector result is not the next RMSNorm's quality result. It independently found negligible 5% local benefit from unchanged expert-output omission even after granting the weaker direction-only observer for free.

The next useful experiment captures the actual post-add producer (or residual and shared branch separately), evaluates a paid changed coordinate on disjoint complete-model loss, and prices its direct consumer. Ordinary Q8/expert physical-time diagnosis remains independent. No GPU, selected native map, weight image, service or serving default changed.

Reproduce the census in seconds with `python3 tools/qwen-moe/rms_observation.py`; it checks the GGUF header against the inventory, verified acquisition receipt, positive epsilon and forty gain payloads, and writes `../../data/qwen-moe/rms-observation/receipt.json`. It does not run the model.
