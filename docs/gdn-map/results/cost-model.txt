Three state contractions per token are unavoidable in these formulas:
  k-side (delta needs g S_(t-1) k_t), q-side (output), rank-m update.
  floor 49,152 lane-ops/token/head = 15.3 us/token over 48 layers.
  deployed serial is 2.34x that floor, the narrow layout with
  identities A and B is 1.08x, block WY c=8 on the same layout 1.13x.
  Reductions are a layout property: both forms contract the state over the key
  index twice per row per token, so the block form does not remove them.
  The block form counts LOWER than the unmodified deployed serial form
  (102,536 against 115,200), because it drops the decay pass. Its only
  adverse comparator is serial + identities A,B at the SAME layout, where it
  counts 55,432 against 52,992: more counted arithmetic, by
  the token-mixing terms. Scheduling, dependence and matrix units are not
  represented here, and any of them can reverse that on a real machine.

At m=128 the measured state kernel is 143 us/token, above both columns.
At m=1 the traffic column dominates the work column by a factor of tens, and
PLAN.md's 1,270 us/token decode phase sits near it. Neither observation is a
proof of what binds either regime.

For a dense state array and an unconstrained q_t, o_t = S_t q_t touches every
element, so the read cannot move within that representation. The write can:
nothing outside the head reads the state between tokens.
