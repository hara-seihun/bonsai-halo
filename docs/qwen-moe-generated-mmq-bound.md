# Generated 32-stream routed MMQ: the selected width attains the native slot floor

Two generated 32-stream steps on the installed Qwen runtime expose the missing route geometry behind the [exact full-head J16/J32 speed panel](qwen-moe-generated-stream-j16.md). Each sequence starts from an eight-token prefix shifted along the same natural-text passage and feeds back its own greedy token. Every step requests all 32 full-vocabulary heads. A backend top-k callback records eight expert IDs in each of forty layers. Its tensor is padded to a 1024-byte row stride despite 32 bytes of IDs per row; the first capture failed a deliberately strict stride assertion, and the retained failed wrapper log records that. The corrected observer reads each row at its native stride. The uninstrumented and observed arms produce the **same 96 greedy decisions** (including setup), but the callback cuts graph fusion: these are observed routes, not proof that the uninstrumented target takes precisely those routes or that its logits are bit-identical. The [separate selected-width panel](qwen-moe-generated-stream-j16.md) establishes complete-head bit identity and measured whole-model time without this callback.

Across 80 layer-steps the captures have 20,480 assignments in 6,853 distinct (layer, expert, step) groups. The largest group has 32 assignments. Thirty groups exceed 16 assignments. There are 2,760 singleton groups, 1,421 doubletons, and 2,672 groups with three or more assignments. This is actual grouped-expert occupancy on generated states, not independent uniformly random routes or a new grouping scheme; native `mul_mat_id` already groups them.

| Native gate/up tiles across both steps | J32 control | selected J16 | free per-group J16/J32 |
| --- | ---: | ---: | ---: |
| logical full-image passes | 6,853 | 6,883 | 6,853 |
| active row/column tiles | 109,648 | 110,128 | 109,648 |
| issued full-tile output positions | 224,559,104 | 112,771,072 | 112,771,072 |
| staged activation columns over row tiles | 3,508,736 | 1,762,048 | 1,762,048 |

The down projection has twice the output rows and twice the listed row/position/staging counts, with the same image-pass counts. J16 and J32 both use I64 and 128 threads. For a group of size `s <= 32`, any native full-width tile needs at least `16 ceil(s/16)` output columns: all compiled J are multiples of 16, and `ceil(s/J) J` cannot fall below the smallest such multiple. J16 **attains the lower bound for every observed group**, including the 30 groups larger than 16. Group-specific J32 for just those 30 reduces one image pass each without removing a single output position or staged activation column; it requires mixed dispatch and potentially changes occupancy and scheduling. This is an exact optimum **inside the native one-J-per-group MMQ tile grammar**, not an ISA-independent bound on packed expert inference, nor a bit-identity proof for a not-yet-built heterogeneous kernel.

Granting free dispatch, perfect image reading on every logical pass, and free reuse nowhere else, the hypothetical mixed schedule removes 57,294,848 bytes from a 17,170,805,760-byte grouped complete one-read demand for the two 32-stream steps: **0.3337%**. This denominator charges each nonexpert image once per step, one embedding row per stream and every selected grouped expert image pass; it is not the ungrouped 64-token stream. The 57 MB is a conditional *logical* upper opportunity for eliminating those repeat passes, not measured DRAM bytes or a bound on timing (the native implementation may cache them or pay a disproportionate partial-tile cost). The 480 fewer row/column tiles across the two steps and launch/dispatch costs also need measurement before any new schedule. Unlike the position reduction that justified selected J16, adapting J32 on this generated shape only chases a small repeat-pass term.
