# No complete Q5_K/Q6_K down-superblock reuse across installed Qwen experts

**Decision (September 24):** Do not build a same-position, full-packed-superblock dictionary for the installed expert-down bank. Across **all 40 layers, 256 experts and 4,096 output-row/K256 block positions per expert** (41,943,040 blocks, 7,488,929,792 packed bytes), there are **zero** byte-identical blocks belonging to different experts at the same position. This is an exhaustive frozen-bank result, not an estimate from routes. Both independent real-text 64-token routed-ID captures have zero equality among their eight experts at a position: 83,886,080 selected block instances and 293,601,280 expert-pair/position comparisons per split. The free same-position block-interning saving is exactly **zero image bytes and zero conditional selected weight-read bytes** in this grammar, before metadata, lookup and indirection. No native implementation, model image, GPU lock or serving default changed.

The Q5_K/Q6_K packed superblock here contains 256 weight codes *and its full scale/minimum metadata* in 176/210 bytes. A canonical block position is `(output row, K256 index)` within an expert. A dictionary shared at that position among experts can replace equal payloads by one payload, leaving the packed values of all consumers intact. Its maximum useful saving is the number of duplicate payloads times the payload size, granting free address metadata and lookup. The zero count closes that exact proposal, including a free route-conditioned choice. It **does not** prove that differing packed blocks cannot have equal decoded values or equal responses on restricted inputs; nor does it reject changed learned expert codes, shorter common fragments, or reuse after an explicitly priced change of input coordinates. In fact, post-SwiGLU down operands differ across experts: equal weights alone would not make two dots shareable without equal operands. The earlier [down operand census](qwen-moe-down-operand-sharing.md) found no full Q8_1 input block equality among eight layer-0 routed experts; this result separately closes the full *weight* payload at all forty layers. A peer is assessing shorter within-expert code fragments, which this full-block equality condition cannot settle.

[`down_packed_reuse.py`](../tools/qwen-moe/down_packed_reuse.py) reads the pinned installed GGUF and `traffic.json` tensor offsets directly. At each layer it constructs two independent 64-bit position-weighted fingerprints for 256×4096 payloads, sorts the 256 candidates separately at each position, and checks the **complete packed bytes** on every adjacent candidate match. A sorted equivalence class of size `c` contributes `c−1` duplicate blocks; the sum is zero. It independently checks pair equality and connected-component redundancy for the actual eight selected IDs on each split. Fingerprints can suggest equality but cannot manufacture a false one: all suggested matches undergo full byte comparison. Shard receipts include full tensor-payload SHA-256, route-file hashes, pinned acquisition hash, input inventory and source hashes. The aggregate [CPU receipt](../../data/qwen-moe/down-packed-reuse/receipt.json) identifies all forty source/input-hashed shards; its source SHA-256 is `a9dd2bdffcf781828d9789af1fe13df28fd206078da47759f710acd8c5324435`. Reproduce in bounded foreground shards with `python3 tools/qwen-moe/down_packed_reuse.py --first 0 --last 10` (then 10–20, 20–30 and 30–40) and `python3 tools/qwen-moe/down_packed_reuse.py --aggregate`. This CPU census does not establish physical DRAM reads or whole-model timing.
