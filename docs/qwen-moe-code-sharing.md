# Frozen Qwen expert code does not share a useful exact route

[Kelana measured identical packed-code reuse](../../kelana/research/moe/code-sharing/README.md) across every expert in the pinned GGUF's layers 0, 19 and 39. Among sixteen seeded, synthetic eight-of-256 routes in layer 0, matching four-byte low-code fragments make up 1.75% of gate and 1.48% of up uses; eight-byte fragments fall to .209% and .169%. At sixteen bytes the matches are below .005%. No complete quantized 256-weight block repeats at the same coordinate across all 256 experts in any inspected layer. In layers 19 and 39, even the short-code coincidences nearly vanish.

The code-only comparison deliberately ignores block scales/mins and Q5/Q6 upper bits. It therefore *overstates* identical operand reuse; it is not a lossless substitute for existing HIP grouped expert dispatch. The proof bounds only a direct common-subexpression grammar where an unchanged packed fragment at the same input coordinate is consumed once for all selected experts carrying that fragment. It does not constrain other packed maps, jointly learned codes, approximate shared bases or token-to-token weight cache residency. Same-position reuse is what matters for one token, because a code match at another coordinate multiplies a different activation.

Layer 0 has many four-byte matches when looking at all 256 experts at once, but a token routes to eight; indexing every fragment for that conditional sharing is a poor trade. One-byte indices already cost 25% of four-byte payload or 12.5% of eight-byte payload, before dictionary bytes, gathers, scales and routing, for 1.75% and .209% optimistic gate route-local sharing respectively. No native timing or model quality changed. The next useful question is code **construction**, with actual router/activation captures and the weighted expert sum as the observation, rather than another dictionary over the frozen GGUF bytes. The dense sub-bit pilot's complete-model failures make a local response win insufficient for adoption.

The source, declared grammar and per-bank table are in Kelana. The [three raw CPU receipts](../../data/qwen-moe/code-sharing/) include source, inventory and GGUF-header hashes, route IDs and per-route fractions. The pinned model file was fully verified during acquisition, not rehashed for every CPU panel. Neither Bonsai's executable nor its resident service was changed; there is no inference speedup claim.
