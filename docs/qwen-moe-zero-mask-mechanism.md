# The Qwen routed hidden zeros are fixed dormant expert channels

The surprising expert-fixed mask in the [grouped zero-block study](qwen-moe-zero-group-tiles.md) is a **weight property**, not an accidental correlation between 239 text tokens. In the installed layer-0 GGUF, decode the complete 256-expert Q4_K gate and up banks and Q5_K down bank using the installed libggml dequantizers. For every expert, the gate and up have *exactly the same all-zero output rows*. There are **54,257 inactive channels of 131,072 (41.395%)**, from 2 to 419 per expert; neither bank has a zero row outside this common mask. The decoded down columns at these positions are **not zero** (all 54,257 have a nonzero element), so a down-only weight sparsity census misses the mechanism. Its routed activation is zero, hence those down columns have a zero operand on the observed native route.

A separate capture at the **pre-SwiGLU gate and up boundaries** of the selected native graph reproduces the prior SwiGLU capture exactly on both 113-token train and 126-token held prompts: all 176,260 / 204,177 zero slot-coordinates coincide between gate, up and SwiGLU. For each of the 256 decoded experts, every selected slot's 512-bit zero mask equals its static decoded gate/up row mask, with **zero mismatches** on both captures. The capture hashes identify full tensor values and IDs, not just masks. In the original official BF16 layer-0 slices for experts 0–15, **3,521 of 8,192 channels (42.981%)** have both full gate/up rows *and* the full down column composed entirely of the same signed tiny BF16 values (words `469` and `33237`, magnitude `7.82438427e-38`). Those masks match the installed GGUF's zero gate/up rows exactly on all 8,192 positions. The earlier spot-check for *literal* BF16 zero rows was true but missed these signed sentinel rows. The BF16 result is restricted to the sixteen acquired experts; the installed GGUF census covers all 256 in layer 0.

## Map and bound

For the decoded GGUF real-weight map, each zero gate/up row has zero dot product for **every finite input**. SwiGLU therefore produces zero there; deleting that coordinate before the down projection is exact as a real-number map, without recovering either constituent output. This is a joint gate/up/down observation: one expert-specific 512-bit mask identifies simultaneously unused gate/up outputs and down input coordinates. It applies regardless of routing frequency or prompt-token grouping. Native FP32 bit identity under a *changed* dot schedule, Q8_1 group quantization, Q5_K block regrouping and output accumulation is not established by this real-map proof. The two real-text captures establish that the selected native execution actually produced the zero gate/up/SwiGLU values on their finite domain, not all possible FP32 inputs.

It grants free repacking and indexing, proportional packed bytes in all three projection banks, unchanged group-scale fidelity, and all layers repeating layer 0. The selected GGUF stores dense Q4_K/Q5_K groups and reads their dormant coordinates; only an actually compact *joint* image with a consumer can earn these bytes. The held-route complete-model free joint-image byte opportunity is only 0.24754%, not the conditional 9.212% layer-0 extrapolation. Do not build the all-layer sparse image from this layer-0 rate. For an exact installed-reference candidate, retain each old quant group's scale, code and FP32 contribution order where required, and measure whole-model prompt, decode and batched rates rather than extrapolating this byte bound. The already grouped native expert scheduler is the control, not the discovery.

```sh
python3 tools/qwen-moe/zero_mask_mechanism.py --first 128 --last 256 --output ../../data/qwen-moe/zero-mask-mechanism/part-128-256.json
```
