# Qwen Q8 next-K loads can precede the current dot in compiled gfx1151 ISA

The selected one-row Q8_0 × Q8_1 MMVQ streams 713.032 MB of modeled one-read Q8 projection weights per token over forty width-8192 calls; its earlier traced group duration was 3.887 ms/token. Those figures do **not** measure physical transactions or establish a memory-latency stall. The preceding [C++ preload](qwen-moe-q8-next-k.md) instead compiled the next packed loads *after* the present FP32 fold. Here the narrower question is whether an executable ISA schedule with two outstanding packed requests before the current integer dot is constructible at the installed shape.

**Yes, in compiled ISA.** A candidate confined to the nonfused one-row Q8 template puts the next weight and activation `global_load_b64` and the current first `v_dot4_i32_iu8` in one ordered AMD inline-assembly block. Its second dot and FP32 fold stay in the template's existing K order; the terminal iteration takes the no-next-load arm. In the steady cyclic body the compiler emits loads at `…C1D4` and `…C1DC`, followed by the current first dot at `…C1E4`. The back edge reaches the second dot at `…C104` and FP32 fold at `…C12C` before the new operands are consumed. The preceding `vmcnt(2)` at `…C1D0` retires present operands, not the just-issued next pair. This establishes an actual *issue-order construction* and refutes the narrower concern that the compiler cannot be made to issue them early. It does not establish latency hiding: the following wait, dynamic branch/exec overhead and cache traffic can erase the available interval.

The candidate preserves each lane's K assignment and uses the same two signed integer dot instructions, Q8_0 half scale, Q8_1 lower half scale and ordered FP32 fold expression. The signedness modifiers in the candidate first dot match the installed `neg_lo:[1,1,0]`. This source/ISA argument does **not** certify finite-logit identity: inline-assembly address/scale handling, terminal iteration and compiler contraction need native full-head acceptance. It is deliberately absent from the selected runtime. The target resource cost is **17→20 VGPR, 25→30 SGPR**, zero spills/scratch/LDS on both, one wave per row. The candidate adds a terminal branch and execution-mask manipulation. No GPU benchmark, image change, default change or service pause was made.
