# Exact source-owned recurrent update with duplicate old rows

The [physical-source writer](qwen-moe-gdn-row-dependency.md) deletes the gathered intermediate for a **bijective** complete batch. Dynamic serving may read one old row for multiple new sequences, or source a row belonging to an inactive sequence. Neither case requires a whole-state gather **in the abstract row-local recurrent map**. A source-owned writer extends the construction to arbitrary repeated sources while retaining exactly the active batch's physical state slots. Its cost is serial fanout within a shard owner, not a free speedup. This is a checked scheduling construction, not an installed Qwen runtime or a resolution of the [failed native 31+1 split](qwen-moe-gdn-singleton.md).

## Domain, schedule and proof

Let live logical rows be `L`, active destinations `D ⊆ L`, and `P:L→physical slots` be injective. Each active destination `d` has one **existing live** source `s(d)∈L`; `s` need not be injective or map into `D`. All inactive rows `L\D` retain their old state. For each `d`, the gathered reference computes `C'[d]=F_d(C[s(d)])`, with a row-local state transition `F_d` and token operands fixed before this state pass. For `d∉D`, `C'[d]=C[d]`. The same construction applies independently to all thirty recurrent layers when their row labels agree.

Partition `D` into groups `G_x={d:s(d)=x}`. Every distinct source `x∈D` gets its own old physical slot `P(x)` as **one** output destination. All remaining destinations get distinct slots from `P(D\image(s))`; their counts match:

`|D| − |image(s)∩D| = |D\image(s)|`.

Sources outside `D` are inactive and therefore never used as destinations. A single shard owner per source `x` loads an old shard fragment, evaluates each `F_d` for `d∈G_x` in the reference's arithmetic order, and writes its assigned output. Its branch assigned `P(x)` is **last** when `x∈D`; earlier branches may write only slots that are not sources of any group. All groups' writes are disjoint, and no other group writes `P(x)`. Thus arbitrary group/CTA order preserves every old source fragment until its owner consumes it. Remap logical destinations to their new assigned physical slots; retain `P` for inactive rows. This proves the complete logical state transition by induction across calls, including duplicate and inactive sources. It does **not** license multiple independent CTAs reading the same source and racing a write: the fanout must be owned together per state shard, or a separate read barrier/snapshot is needed.

Concrete four-row witness: `D={0,1,2}`, inactive `3`, and sources `s(0)=1, s(1)=1, s(2)=3`. Assign output 1 to old slot 0, output 0 to old slot 1, output 2 to old slot 2. Source 1's owner computes output 1 before overwriting slot 1 with output 0; source 3's owner reads untouched slot 3 and writes slot 2. Only **two** old state rows are read for three outputs, no new full-row slot is allocated, and inactive row 3 stays live. A fixed-destination swap and separately scheduled fanout writers both have executable counterexamples in the checker.

[`gdn_fanout_map.py`](../tools/qwen-moe/gdn_fanout_map.py) checks **696** active/source maps up to four live rows, **2,816** two-step group-order schedules including 448 fanout maps and 255 maps with an inactive source. It compares all live outputs after each step to a separately computed gathered map using a nonlinear integer row transition, exercises carried physical labels, asserts disjoint source/write sets, and includes both unsafe schedule witnesses. [The receipt](../../data/qwen-moe/gdn-fanout/receipt.json) preserves the script hash, installed native source object IDs and result digest. The general proof, rather than the finite checker or integer arithmetic, supplies the exact abstract result.

## Online cost and native boundary

For `n=|D|` active rows and `r=|image(s)|` distinct old sources, the state pass reads `r` old full rows and writes `n` final full rows. There is no intermediate full-row gather/scatter or extra persistent state slot. In a row-local arbitrary-transition grammar where every output depends on its old source and every final row must be materialized, these `r` reads and `n` writes are necessary; this is **not** an ISA-independent lower bound or a statement about degenerate/identical transitions. The plan requires an `O(n)` source-group list and new logical-to-physical labels, plus a group launch/schedule; repeated-source work is serialized *within each state shard* and may lose occupancy. It still evaluates all `n` transitions and all requested output heads. For the installed 32-row, 30-layer FP32 GDN geometry, one complete read plus write is `2 × 32 × 524,288 × 4 × 30 = 4,026,531,840` logical bytes. The selected stable-batch writer already reaches this traffic coordinate; a hypothetical dynamic fanout writer could avoid the separate **4,026,531,840 intermediate bytes** of the gathered route. Each duplicate old row would save at most `524,288 × 4 × 30 = 62,914,560` more old-state read bytes under this model. No DRAM or wall-time gain is inferred from logical bytes.

The installed `gated_delta_net_cuda` owns a state shard by `(sequence, head, column group)`, loads `s_shard` into registers, reduces `S·k` and `S'·q`, emits an attention output and stores final state. A native fanout group would have to run the **same FP32 recurrence and reductions separately per destination** while keeping each source shard unchanged until the source-owned overwrite, then carry `P` through `find_slot`, GDN/convolution cache graph construction, extra/zero rows, rollback, serialization and graph reuse. A source group may have very different work from another; a source-indexed launch and GPU-group metadata are additional work not charged in the byte count. The abstract schedule covers live-state single-token calls with complete active destination sets; zero-init sources, K>1 history slots, the current 31+1 split's graph/operand mismatch, and partially committed batches are excluded. Even for a map satisfying the theorem, the existing rejected native writer changed finite logits; source and destination aliases alone did not explain it. Do not select a native route without full-head and serialized-state bit equality.
