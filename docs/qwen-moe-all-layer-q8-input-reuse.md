# Forty-layer routed input codes do not repeat within either real prompt

Does route repetition make an exact `(expert, K-block, Q8_1 activation)` memoizer useful beyond layer 0? The selected Qwen3.6 GGUF callback captured the **actual 2,048-wide post-attention producer and eight route IDs** at all forty layers on two disjoint 64-token texts. The CPU reproduction applies the installed `quantize_q8_1` rule per 32-float block, then checks every `(layer, K, 32-code)` equality; an expert-specific reuse requires this equality *and* the same expert. Native `mul_mat_id` already shares the prepared input among eight experts **within** each token.

| Scope | Producer 32-code blocks | Revisits of the same expert within a layer | Repeated codes at same K | Repeated codes at any K | Repeated full input rows |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 train tokens × 40 layers | 163,840 | 16,493 | **0** | **0** | **0** |
| 64 held tokens × 40 layers | 163,840 | 16,704 | **0** | **0** | **0** |
| Both texts jointly | 327,680 | 35,928 | **13** | **13** | **0** |

The thirteen joint code collisions are all between **token 0 of the two different texts**, at K-blocks 34, 46 or 63 in eleven later layers. In every one the CPU-computed FP16 **input sum differs** (difference at least 0.03125); in six the FP16 scale differs as well. Each Q8_1 block stores codes, scale **and input sum**, so none is a matching prepared operand even across texts. The native sum is a warp FP32 reduction, whereas this diagnostic sums on CPU; the source/result distinction matters. The zero code collisions *within each text* do not depend on either scale/sum computation. The CPU coding uses the native maximum/127 and `roundf` (away from zero) rule, but does not assert bit-for-bit GPU coding at half-integer boundaries. These observed collisions are not native FP32 logit equivalence or complete-model language-quality measurements.

Across the two independent prompts, **0/327,680** producer blocks repeats within its own prompt even allowing arbitrary K permutation, despite 33,197 within-prompt expert revisits. At every repeated route, an exact code-keyed dot memoizer must compute a new value; the proposed persistent hash table has no within-prompt hits before its lookups, even if scales, sums, and all capacity/lookup costs are granted free. With both prompts jointly, the thirteen apparent code hits disappear at the full stored-block boundary. This is a bounded negative for *existing* Q8_1 labels and these real callback prompt producers, not an impossibility result for generated streams, learned lossy labels, or output equivalence under a particular expert weight. Distinct input codes can also happen to yield the same dot for particular weights; that is outside the equality-keyed input-operand grammar.

One layer prepares 64 × 36 = 2,304 Q8_1 bytes per token; all forty layers prepare 92,160 bytes/token, just **0.003509%** of the conditional 2,626,187,904-byte one-read weight stream. This ratio is *not* a whole-model speed bound on activation arithmetic, setup or cache behavior. It explains why an exact persistent activation-byte cache is a poor replacement for the already-grouped expert consumer even if some code repeats. The next useful route is **changed packed producer/weight labels trained against broader routed inputs**, then a paid full forty-layer image and held complete-model language loss; for exact runtime gains, measure ordinary Q8 and expert physical execution instead of another input hash table. The dense sub-bit and ternary conversions already showed why a local fit cannot certify that full-model result.
