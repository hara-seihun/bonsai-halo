# Physical-source GDN writer: a different coordinate for reordered routes

The installed Qwen3.6-35B-A3B no-copy GDN writer is restricted to stable generated 32-stream identity maps. A swapped sequence order has a real cross-CTA hazard under its **fixed destination** schedule: a CTA reading row 1 and writing row 0 may overwrite the old row 0 before another CTA reads it. [The selected runtime and full-model acceptance](qwen-moe-gdn-fused.md) retain the gathered fallback; [the earlier indexed-row analysis](qwen-moe-gdn-index.md) describes snapshots needed if fixed destinations are retained. This note gives a different exact *state-map construction*, not a new installed runtime.

## State-map theorem

Let a complete active batch have distinct logical rows `D={0,...,n-1}` and let `s:D→D` be a bijection of their old logical source rows. Let `P:D→D` be the current bijection from logical cache rows to physical GDN state rows. Each sequence `i` computes the same deterministic shard transition `F_i` on its input, including the Q/K/V/gate/beta values and the same FP32 operation order. The gathered reference writes `C'_i=F_i(C_{s(i)})`. Instead, launch one CTA per independent state shard with **both read and write address `P(s(i))`**, then set `P'(i)=P(s(i))`. Since `P∘s` is a bijection, all CTAs read/write disjoint physical shards. Every CTA loads its original shard before updating that shard; arbitrary CTA order produces exactly the reference's logical state `physical[P'(i)]=C'_i`. Induction gives the same result for any sequence of complete permutations. The consumer can carry `P` as a coordinate; it need not materialize source-order state rows between steps. This proof is valid for native FP32 when `F_i` itself remains exactly the existing kernel's arithmetic; it does **not** prove that a modified graph or CUDA compiler retains that body.

For two rows, the fixed-destination map `s=(1,0)` fails in the CTA order 0 then 1. Source-address writes land on rows 1 then 0 instead, so neither can clobber the other's input. The checker replays **28,449** two-step schedules: exhaustive ordered CTA interleavings and two route permutations up to four rows, plus all route pairs at five rows with reversed CTA order. It compares the logical state after *each* step to a separate gathered reference and includes the failing fixed-destination witness. Its receipt is [`gdn-source-writer/receipt.json`](../../data/qwen-moe/gdn-source-writer/receipt.json), with checker SHA-256, installed native source object IDs and output digest `e7455fa2da64ef98a310f4764f4cb39f71cb61905baddee2848732dcec5992c4`. Regenerate on CPU with `python3 tools/qwen-moe/gdn_source_writer.py`. The finite checker does not replace the bijection proof.

## Executable cost and domain

The logical state transition needs `n` original-shard reads and `n` final-shard writes, **zero full-state gather, scatter or snapshot rows**. In the measured 32-stream, 30-layer, FP32 Qwen state geometry this is the same potential 4,026,531,840-byte *logical intermediate-traffic deletion* already realized for identity maps, not an additional speedup. Physical data paths need the source index `P(s(i))` as **both** GDN input and output address, plus an `n`-entry metadata permutation at every completed call (128 bytes for 32-bit addresses at 32 streams). That metadata and graph dependencies are real costs; no GPU timing, DRAM counter, or whole-model output was obtained here.

The theorem requires injective sources for all CTAs whose input might be overwritten. A shared old row, zero-init row, extra relocation, or an unfinished segment still needing the old value invalidates the simple schedule; snapshot/copy or new allocation is necessary. If the allocator divides a swapped request into 31+1 calls, the second call can still need data from the first call's pre-update state, so the proof cannot authorize changing the installed guard. It also cannot simply reinterpret the recurrent cache's physical addresses: `find_slot` reorders `pos/src/seq_id/tail` and stages `src0` before resetting `src`, while `build_rs` updates extra rows and GDN's next call uses `s_copy` computed from that metadata. A native implementation must carry `P` through **every** GDN cache read, write, zero, relocation, rollback, graph-reuse decision and serialization, and preserve convolution-cache behavior. The same physical GDN row permutation must be valid for all 30 layers. The currently installed runtime does none of this on reordered calls.

The better native experiment is a **full, unsplit 32-stream swap** with a per-layer physical-address map carried through one generated step, first recording exact full heads and entire serialized state against the gathered reference, then measuring matched full-model generation and the unchanged prompt/singleton paths. If the allocator insists on 31+1, the first question is a source-lifetime witness across both calls; a per-subcall identity test is insufficient. Prompt and singleton failures in the earlier overbroad native arm remain unexplained by this proof and remain on the gathered path. This construction is a cheaper exact scheduling candidate in a stated row-permutation domain, not a claim that it repaired those failures or sped up the selected executable.
