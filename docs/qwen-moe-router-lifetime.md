# A safe fused Qwen router is not sufficient for MTP-width identity

The selected native `3f552c2` allocates two-row router logits and normalized weights with a cross-row overlap; simply forcing fused top-k races. We changed the *graph lifetime* rather than deleting its guard. Native source `81326f729efd7b5bfa2ea5461e9027e43dcc9480` adds a zero-compute reshape/view of router logits as a graph root after normalized weights, only for 2–8 token Qwen softmax/normalization graphs. The ggml gallocr counts the view as a late child and retains the input buffer through the fused write. The source is packaged with its build and bundle under `data/qwen-moe/runtime/81326f7…` and pushed to `runtime-source.git` (`build-81326f7…`), **but is not selected**.

## Construction and bounded acceptance

The candidate's no-cut callback sees layer-0 two-row logits occupying 2,048 bytes and normalized weights starting **2,176 bytes** after the logits base: no overlap. In the final 2-row device trace, three evaluations dispatch **120 `topk_moe_cuda<256,false>` kernels** (40 layers each); the two long prompt evaluations retain **80 separate softmax and 80 argsort** kernels. The graph-root view adds no device kernel in this trace. The same two-row allocation was independently observed on the initial unrestricted candidate, whose full-prompt arithmetic *changed*; that failure is retained. Restricting the view to at most eight tokens restores the installed 465-token/32-step acceptance: the packaged executable's **7,946,240 FP32 logits and 32 greedy IDs** have exactly the installed reference hashes. Single-row plain decoding remains the original graph.

On the first five natural-text continuation rows, the final no-cut target-only width panel compares 40 full-vocabulary rows across widths 1, 2, 4, 8 and offsets 0–3: **zero differing logit bits**. This is an achieved graph-lowering construction, not yet evidence that it fixes speculative decoding. A matched 64-token, depth-1024 unprofiled panel measures the candidate and selected control at 51.397 and 51.322 tok/s respectively (two noisy repetitions; single-row code unchanged). For an eight-token prompt, the control and candidate's two three-repetition panels produce 148.306/202.799/217.078 versus 165.898/210.452/226.921 tok/s and, reversed in process order, 156.733/203.828/217.791 versus 156.720/206.345/221.506. These prompt rates are not complete-generation gains; host work and first-use effects affect the panel.

## The decisive longer replay

The same source on the **entire 96-token greedy list continuation** exposes another width-dependent map. Each arm replays identical plain-produced token IDs at the same causal positions, asks for every head row, and compares to width-one. All 97 rows at width 1 and **both width-2 offsets** agree bit-for-bit. Every width-4 offset first disagrees at generated row **12**, and disagrees on **85/97** rows. Width 8 disagrees beginning at row **1**, on **96/97** rows. In total the long panel compares 776 vocabulary rows and finds 108,267,393 differing float bit patterns. At the original MTP near tie, every width-4 offset still flips plain ID **4980** to **33565** at row **71**. An independent no-cut address panel reproduces these counts. Its layer-0 width-4 and width-8 router normalized outputs start beyond the entire input-logit allocations (offsets 4,224 after 4,096 bytes and 8,320 after 8,192 bytes). Thus the original *layer-0 cross-row alias* is eliminated on these shapes, but that alone does not preserve the requested plain greedy stream. It does not prove every layer fused or identify the later numerical fork.

The initial unrestricted graph-root candidate was itself rejected: it matched the five-step width panel but changed **every** 465-token acceptance row relative to the selected reference, including the first greedy ID. Restricting to <=8 restores the prompt map and exposes the longer verifier failure rather than hiding it. No MTP/default/runtime/image was changed. The packaged candidate remains an explicit experiment, not an unused alternate in the selected runtime.
