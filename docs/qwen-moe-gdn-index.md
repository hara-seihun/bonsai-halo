# Exact cache-row hazard for a direct Qwen GDN consumer

The selected Qwen3.6-35B-A3B native runtime gathers 32 recurrent-state rows before each of 30 GDN layers in an actual generated 32-stream step. The [paired device trace](qwen-moe-generated-phase.md) measures 18.8–19.2 ms/step for these gathers. There are **two distinct direct-index constructions**: a separate GDN-output/scatter kernel is safe for arbitrary main-row permutations but merely moves the full-row copy *after* GDN, while preserving the selected fused cache write needs a precise row-map guard (and sometimes pre-GDN snapshots). Deleting the gather launch without pricing the replacement scatter cannot establish a saving.

## Contract and two constructions

At one layer, after the existing zero operation, let `m[i] = s_copy_main[i]`, `x[e] = s_copy_extra[e]`, and `d[j] = rs_head+j` for `0 <= i,j < n_seqs`. The original graph gathers *all* `cache[m[i]]` and *all* `cache[x[e]]` into independent temporaries before relocating extra rows to `rs_head+n_seqs+e`. GDN then consumes the gathered main rows, computes the existing FP32 recurrence, and writes main results to `d[j]` (the selected CUDA graph can fuse the snapshot cache copy into GDN). The new observer must preserve the old rows read by each sequence **and** the final cache rows; neither arithmetic order nor GDN output bits are changed by this row-label construction.

**Split-write construction.** A GDN kernel reads all `cache[m[i]]` but writes new states only into a disjoint temporary; a dependent separate `SET_ROWS` kernel scatters those states to `d[i]`. The kernel boundary orders *all* main reads before *any* main writes, so even a full permutation of sources is safe without a main snapshot. Keep the extra-row snapshot before GDN and defer its destination copy until after main reads if extras exist. This is the native direct-row owner's currently proposed construction with a guard `n_rs == n_seqs` (no extras). The property relies on the two launches remaining separate; if graph fusion changes that, re-evaluate the guard below.

**Fused-write construction.** If GDN writes new state directly to `d[i]` as it does in the selected path, define the hazardous source set

```
H = { m[i] : m[i] = d[j] for some j != i }.
```

Snapshot each distinct row in `H` before launching the direct-index GDN. Its CTA `i` reads that snapshot when `m[i]` is staged, otherwise reads `cache[m[i]]`. Keep the existing extra `get_rows` snapshot before GDN; relocate its saved contents only *after* GDN. Main and extra destinations are disjoint. This ordering means no extra write can clobber a main input before its read, no GDN write can clobber a saved extra source, and no GDN writer can clobber another CTA's unstaged main input. A CTA reads its own complete initial state into registers before writing its own result. The ordinary zero operation must still precede all snapshots. With `H` empty, the fused-write path can remove the main gather entirely; a nonempty `H` needs either selective snapshotting or the original full gather. The existing standalone `qwen35.cpp` rows path explicitly describes the *extra relocation* risk but not this fused main-write/main-read risk.

For the declared grammar—arbitrarily ordered concurrent CTAs, each loading its own initial state then writing its own distinct `d[i]`, no grid barrier, no changed cache destination, no recomputation, no reordering of dependent FP32 operations—**every distinct row in `H` is necessary** to snapshot before the kernel. If `m[i]=d[j]` and `j!=i`, schedule writer `j` to finish before reader `i` starts: without a snapshot, `i` sees the new row. Conversely the construction above is sufficient for every CTA order. This is a row-level storage/scheduling theorem, not a lower bound on a different serial, multi-kernel or temporary-output algorithm. Duplicate main source indices require no additional snapshots if they are not overwritten by another CTA. Merely checking `n_rs == n_seqs` does not certify safety: a two-row swap has two hazardous sources even with no extras.

`tools/qwen-moe/gdn_index.py` computes `H` from a source-index map and replays reference versus constructed cache states with opaque row labels. Its bounded exhaustive run enumerates **8,827 schedules** over one to three main CTAs, zero or one extra row, all source-index maps in the declared finite range, and every CTA order. **3,904 schedules fail with no main staging; none fail with `H` staged.** Removing any single distinct staged row fails under some order. The first witness is `head=1, main=[0,1], order=[0,1]`: CTA 0 overwrites row 1 before CTA 1 reads it. A stable `head=40, main=[40,41,42,43]` needs zero main staging; swapping the first two sources stages rows 40 and 41. The exhaustive replay checks the ordering lemma on small row maps, while the general argument above proves arbitrary map size.

## Price and inference boundary

Qwen's state row is 524,288 FP32 values, **2,097,152 bytes**. At 32 streams, the selected gather writes 67,108,864 bytes/layer, 2,013,265,920 bytes across thirty layers, and reads the same quantity from the old cache. Let `B=67,108,864` bytes/layer. The **selected fused path** pays `B` gather read + `B` gather temporary write + `B` GDN input read + `B` fused cache write = `4B` logical state traffic. The **split-write direct path** pays `B` direct GDN cache read + `B` GDN output temporary write + `B` scatter read + `B` scatter cache write = **the same `4B`**, or **8,053,063,680 state bytes across thirty layers** in either path. The split removes a gather launch but replaces it with a scatter launch; it cannot claim a logical byte saving from this construction. This equivalence excludes other GDN operands, extra rows, cache effects and partial output writes; it does not predict equal time. It directly changes the native acceptance criterion to combined GDN+copy time, not missing gather time.

For the fused-write path, stable identity `m[i]=d[i]` gives `H=∅`: direct reads can eliminate both the gather's `2B` transfer and its temporary, while GDN's required state read/write remain. A full 32-row permutation with no fixed points instead requires all `B` bytes/layer in snapshots under this concurrent-CTA grammar. Extra-state snapshots are retained and charged separately. Actual generated `s_copy_main` values were not recorded in the trace, so it does **not** certify the identity-map case. The traced 19 ms is the maximum *measured gather duration available to remove*, not a whole-model speedup or a claim about physical DRAM bytes. Direct random-cache reads may cost more than contiguous temporary reads.

[CPU certificate and installed-source identities](../../data/qwen-moe/gdn-index/receipt.json) tie this finding to selected native revision `3f552c2`, its source bundle, and the generated-phase trace. Native/GPU/runtime/service unchanged. The independent direct-row engine owner received this guard before native acceptance. The decisive next measurement is to compare the split-write direct arm's **combined GDN plus scatter** against the selected **GDN plus gather**, with full-head logit bits and cache state transitions. If the no-copy fused-write arm is pursued, first capture actual `s_copy_main` maps on generated 32-stream calls and select it only where `H=∅` (or stage exactly `H`). No source-level reorder of FP32 GDN is licensed by this proof.
