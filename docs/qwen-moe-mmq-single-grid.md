# One grid can carry both Qwen expert MMQ widths

The builder-free [striped construction](qwen-moe-mmq-striped.md) launches a J=16 grid and a J=64 grid for every expert projection. At eight stripes each, that is 163,840 scheduled CTAs across the forty held prompt layers, with 39,664 active. But the native gfx1151 configuration uses 128 threads for J=16 and 256 for J=64. This suggests a different exact task coordinate: launch one 256-thread grid `(expert, stripe)`. An expert chooses its unique J from its sorted `expert_bounds`. A J=64 CTA visits tile indices `s, s+k, ...`; a J=16 CTA has two independent 128-thread halves, with half `h` visiting `2s+h, 2s+h+2k, ...`. Each half executes the existing logical 64-row by 16-column tile, while a J=64 CTA executes the 128-row by 64-column tile. Down uses its own doubled output-row list. Gate, up and down remain separate projections, and this changes neither quantization nor expert gathering.

For T J=16 tiles, the two-half assignment partitions `[0,T)` without duplication and gives at most `ceil(T/(2k))` tile bodies per half. J=64 has at most `ceil(T/k)` per CTA. Both bounds follow by pigeonhole for their respective fixed stripe grammar. Native J=16 groups in the captured 126-row prompt have exactly sixteen gate/up tiles, and J=64 groups have eight or sixteen. At k=8, J=16 halves each execute one gate/up tile and at most two down tiles; J=64 CTAs execute at most two gate/up or four down tiles. These are task-list bounds, not GPU instruction or latency bounds.

The CPU witness compares the emitted tile coordinates as unique sets with the independent compact descriptor queue on all 80 captured layer/route sets. Every tile matches. On the forty-layer held whole prompt, per projection:

| Grid | Launched CTAs | Active CTAs | Gate/up tile bodies | Max J16/J64 gate chain | Max J16/J64 down chain |
| --- | ---: | ---: | ---: | ---: | ---: |
| Two separate J grids, k=8 | 163,840 | 39,664 | 75,088 | 2 / 2 | 4 / 4 |
| One mixed grid, k=4 | 40,960 | 19,832 | 75,088 | 2 / 4 | 4 / 8 |
| **One mixed grid, k=8** | **81,920** | **39,664** | **75,088** | **1 / 2** | **2 / 4** |
| One mixed grid, k=16 | 163,840 | 40,056 gate; 79,328 down | 75,088 | 1 / 1 | 1 / 2 |

The one-grid k=8 schedule halves launched CTAs and removes one of the two body launches per projection relative to separate striped grids. It also halves the scheduled 256-thread CTA entries relative to selected J=64, though a 128-thread J=16 CTA in the two-grid control costs fewer threads. Counted threads are 20,971,520 for the mixed k=8 grid, 31,457,280 for two k=8 grids, and 41,943,040 for selected J=64 across forty layers. These are launch geometry, **not executed instructions**. The selected global J=64 route has different tile work; the mixed body has 75,088 gate/up tiles and the selected route's reference logits still require a native acceptance check.

There is a material implementation boundary. Native `mul_mat_q<type,J>` compiles `nthreads`, shared memory and synchronization for one J at a time. Branching from a 256-thread CTA into the existing 128-thread J=16 body would deadlock at CTA-wide `__syncthreads`. A native mixed kernel needs subgroup barriers, distinct shared-memory slices and a resource allocation that admits both branches. If doubling J=16 shared memory or inheriting J=64 register pressure cuts occupancy, the static savings can vanish. A J=64 group has only 32 to 168 active CTAs per held layer at k=8, so its tail can still underfill gfx1151. The arithmetic inside each logical tile can keep its input order and FP32 chain, but the host coordinate proof is not a device bit-identity proof.

This construction narrows the next experiment: first compile the heterogeneous kernel and inspect its VGPR/LDS occupancy and tile outputs. Then compare k=8 against selected J=64 and the separate-grid striped body under `tools/run-batch-compare`, with exact installed logits and equal complete-model prompt, independent-stream generation and output-head work. If the mixed body cannot retain native resource occupancy, use separate specialized launches rather than claim half the CTAs as a speedup.
