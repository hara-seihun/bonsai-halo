# Split-row Qwen K/V: correct host scatter targets, missing first segment's saved cell

The [complete saved-cell test](qwen-moe-gdn-row1-destination.md) found no relocation of logical sequence 1's missing newest K/V. This experiment follows its *host* KV scatter index on the unchanged Qwen graph and separately isolates the HIP `SET_ROWS` operation. It does **not** capture the unsaved K/V producer or a pre-export device cache cell.

The selected native source's `llama_kv_cache::set_input_k_idxs` sets `global_index = physical_stream * 256 + local_cell` before the graph runs. A research-only env-gated log added to that host function, in native branch `research-row1-index` at `1afabeaee`, records the actual indices of the matched 32-sequence, three-step panel. In normal order the third step writes streams `0..31` at cell 9 (indices 9,265,...,7945). In the reordered, gathered 31+1 call, the *first* segment's row 0 targets **stream 1, cell 9, global index 265**, and the other 30 rows target streams 2..31; the singleton segment targets **stream 0, cell 9, index 9**. All 32 destinations are unique and in range. `set_input_v_idxs` uses the same `sinfo.strm` and `sinfo.idxs` in the nontransposed FlashAttention V path, although V indices were not independently logged.

Despite the valid host target, the saved reordered stream-1 cell has **0/512 nonzero halves in K and V at each of ten attention layers**. The normal stream-1 cell has 512/512 nonzero halves at each layer. The result excludes an erroneous *host index calculation* as a sufficient explanation for these zero saved cells. It does not prove that a producer was nonzero, the device received the input index, the graph's fused `SET_ROWS` wrote it, or serialization read the correct device cell. The first physical row of the 31-row segment is the distinctive boundary; the singleton destination is not the missing one.

An independent no-model HIP `ggml_set_rows` graph uses the actual 31 destination indices, 512 F32 input coordinates per row, an FP16 `[512,8192]` zero-initialized cache, and reads all 32 addressed cells after computation. **16,384/16,384 FP16 halves match** (including all 512 nonzero halves of first stream 1; stream 0 remains zero as intended). This rejects a generic standalone first-row-of-31 `SET_ROWS` omission on gfx1151. It cannot exclude the full graph's RoPE/write fusion, buffer aliasing, missing producer, device index upload or cache export. The direct follow-up is a graph-resident side-band probe of K/V *before* `cpy_k`/`cpy_v` and a disjoint device-cache observation *after* each writer, preserving the full-head/state comparison; another standalone SET_ROWS spelling is not the next question.

**Instrumentation acceptance limitation:** normal-order diagnostic heads and the entire 2,114,206,957-byte state reproduce the original gathered panel bit-for-bit. In reordered execution, the diagnostic's third-step logical sequence 1 head differs in all 248,320 words from the prior gathered control, and the whole-state hash differs, despite all twenty missing K/V cells remaining zero. The rebuilt library with the trace env unset instead matches the original *direct* swapped arm's head and state hashes; the gathered baseline was not reproduced by this diagnostic build. Do not use the diagnostic head as an accepted exact-map repair or install its native branch. The host index and the isolated `SET_ROWS` result survive this limitation, but a proposed fix must re-establish both baseline arms' full-head and state equality on the selected binary.
