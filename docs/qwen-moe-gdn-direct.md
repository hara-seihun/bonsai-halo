# Qwen 32-stream GDN: direct indexed read with a split write is a traffic swap

The selected Qwen3.6 runtime's 32-stream generated step spends about 19 ms in thirty large recurrent-state gathers. An opt-in native experiment removed **all thirty** by reading the indexed cache row in the GDN kernel. It preserved every bit of 128 requested full-vocabulary rows in four alternating complete-model processes and all 96 rows in the paired device traces. But writing the state back with a separate `SET_ROWS` kernel costs about 22 ms; the combined state phases are essentially unchanged. This construction is **not selected**. The selected on-demand runtime, GGUF and resident service remain unchanged.

## Arithmetic and state contract

Source base `3f552c2ef572707f05746bdc84c1788792523d62` uses `n_rs_seq=0` on this Qwen path, including the actual 32-sequence generation shape. This matters: simply borrowing Qwen35's existing *ring-only* indexed-state entry did not activate the new map. The first probe's guard required `n_rs_seq>0`, so both arms still launched thirty large gathers; its failed-arm logs and traces remain in the data directory. The working experimental patch extends the non-ring GDN entry. Its GDN kernel reads source row `s_copy_main[seq]`, preserving the identical per-element arithmetic, register accumulation and output state. The output goes to the existing result buffer; a **subsequent, separate** `SET_ROWS` kernel writes the cache. Only when `n_rs == n_seqs` does the patch select this path, because the existing cache view would otherwise move extra rows before GDN reads its main sources. The source patch is retained as evidence, not installed or merged into the selected engine. Its committed native source `3a312075f2ea331597ee3698d6e278f98a982654` is also in `runtime-source.git` under `research-gdn-split-rows`; that is research custody, not the `runtime/current` selection.

Splitting the writer is important even without extras. A fused writer CTA for sequence `j` could overwrite a different sequence `i`'s indexed source before CTA `i` reads it. The separate launch orders *all* main reads before *any* writes, including when source indices are permuted. A future fused in-place candidate needs an explicit cross-sequence alias guard or pre-GDN staging. The independent [state-index certificate](qwen-moe-gdn-index.md) owns that hazard's exhaustive replay and conditions. Merely moving extra relocation after a fused GDN does not fix it.

## Equal-work whole-model panel

`tools/qwen-moe/generated_stream_j16.cpp` seeds 32 independent sequences with shifted eight-token natural-text prefixes, feeds back their greedy tokens and requests **all 32 vocabulary heads** on each generated step. Batch/ubatch 512/256, 8 CPU threads, full GPU offload, flash attention, context capacity 8192, occupied positions 8–11 and the selected expert J16 policy are unchanged. The patch is an environment-selected *same-binary* arm. Four alternating processes in control/direct/direct/control order each calculate 128 full heads (127,139,840 FP32 bytes); all four output hashes are `c9b75afbf704a6786a0e…` and all greedy decisions agree. Three generated steps average 162.810, 145.773, 145.344 and 148.456 ms/step respectively, or 196.55, 219.52, 220.17 and 215.55 aggregate tokens/s. The first control is an outlier; the wrapper reports 2.3 competing host cores, so this panel cannot establish a gain. The separate two-step paired traces agree bit-for-bit on 96 full heads, SHA-256 `359aebfd4af6ee361f620920c4069aa688f5a6fe0832f4f40995df6d3ed68fb1`.

| Device ms per generated step | Control step 1 / 2 | Indexed split-write step 1 / 2 |
| --- | ---: | ---: |
| GDN core, 30 kernels | 34.255 / 33.705 | 31.661 / 31.650 |
| Large state gather, 30 kernels | 19.607 / 18.854 | **0 / 0** |
| `SET_ROWS`, including 20 unrelated launches | .069 / .055 (20 calls) | **22.295 / 22.334 (50 calls)** |
| **GDN + large gather + all `SET_ROWS`** | **53.931 / 52.614** | **53.956 / 53.984** |
| All summed device kernels | 138.667 / 138.354 | 135.814 / 138.917 |

The trace is not a DRAM counter. The unchanged 20 unrelated `SET_ROWS` calls contribute under .07 ms, so the added thirty state scatters account for essentially the entire ~22-ms new category. GDN's internal duration alone falls about 2 ms; reporting only that or the missing gather would misrepresent the complete region. Host and clock variation also move other phases; neither device-sum ratio is a measured whole-model speedup.

## Why this construction cannot remove the state-copy traffic

Each selected state row is `128*128*32*4 = 2,097,152` bytes. Thirty layers times 32 sequences carry **2,013,265,920 bytes** of state per generated step. In the selected fused-cache schedule, the gather reads the cache and writes a temporary row; GDN reads that row and writes the new state directly to cache. In the split schedule, GDN reads the cache and writes a temporary result; `SET_ROWS` reads the result and writes the cache. Both move **four row-images**, or 8,053,063,680 logical bytes per step, counting cache and intermediate accesses once; both require a full materialized state on one side of GDN. This is a *family traffic identity*, not physical DRAM bytes or a universal lower bound. It explains why removing a 19-ms gather need not save time. Even granting free addressing, the split cannot delete any of these four reads/writes; only fusing the indexed consumer with an alias-safe direct cache write removes the intermediate write/read pair (4,026,531,840 logical bytes per step). Such a fused program must satisfy the cross-CTA hazard certificate and keep the installed FP32 reduction and state transitions.

[The raw receipt](../../data/qwen-moe/gdn-direct/receipt.json), SHA-256 `093f758406de48f3a57ace5902bafe2560060b025e0b3b94ca14d0c51b2d1949`, hashes the native source patch, candidate libraries, probe, complete logits, trace CSVs and wrapper logs. The patch at `gdn-direct/split-rows.patch` is SHA-256 `27e231db7e32c45be592d97e1f89471b105c983feb68a3a4e04ae17e4586ca34`. The replay analyzer is `tools/qwen-moe/gdn_direct_result.py`; the first wrong `n_rs_seq` guard and a profiling output-directory failure remain in that data directory. Each GPU panel used `tools/run-batch-compare`, released its lock and restored `bonsai-halo.service`. Its `systemd-run` scope now disables environment expansion before passing shell payloads: the first attempted alternating panel otherwise overwrote every arm's output under `paired--.f32`; the repaired wrapper passed a real shell-variable probe and the repeated panel.

**Next:** either guard the actual `s_copy_main` row map against cross-CTA write/read aliases and fuse safe indexed GDN reads with cache writes, staging only hazardous rows, or choose a different state representation that removes a full state transfer. Test cache transitions as well as full logits and measure GDN plus scatter plus generated wall time. Do not port split `SET_ROWS` solely because the gather disappears.
